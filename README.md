# Оценка риска закрытия ресторана в первые три года

## Бизнес-задача

Перед открытием ресторана предпринимателю нужно понять, какие допущения
бизнес-плана стоит перепроверить до вложения денег. Проект даёт
дополнительный сигнал для такой проверки.

В локальном приложении Streamlit пользователь вводит восемь характеристик
заведения: тип кухни, тип локации, наличие франшизы, опыт владельца, запас
стартового капитала в месяцах, ценовой сегмент, количество мест и размер меню.

Модель рассчитывает оценку риска. При оценке 0.35 или выше приложение
показывает сигнал для дополнительной проверки. Например, предприниматель
может пересчитать, на сколько месяцев хватит стартового капитала,
если выручка окажется ниже плана.

## Ограничения

На тестовой выборке модель выявила 4 100 из 4 447 ресторанов, которые
не достигли трёх лет работы, и подала 3 455 ложных сигналов.
Сигнал можно использовать как повод для дополнительной проверки заведения.
Поэтому оценку следует использовать вместе с финансовыми расчётами
и анализом конкретной точки. Применимость модели к ресторанам Бишкека
отдельно не проверялась.

## Итоговая оценка модели

В демо используется логистическая регрессия с семью признаками:
тип локации, франшиза, опыт владельца, запас капитала, пешеходный поток,
плотность конкурентов и наличие плана продвижения.

На validation короткая форма показала AP 0,7501, а версия с 11 признаками —
0,7511. При одинаковом объёме проверки в 1 800 заведений короткая форма
выделила 1 465 закрытий, на шесть меньше полной формы.

На общей тестовой выборке из 9 000 заведений Average Precision выросла
с 0,6721 у первой версии до 0,7499 у второй. Границы уровней выбраны
на validation и применены к test без перенастройки.

| Уровень риска | Заведений | Не достигли трёх лет | Доля закрытий внутри группы |
|---|---:|---:|---:|
| Низкий | 2 694 | 594 | 22,05% |
| Средний | 4 483 | 2 374 | 52,96% |
| Высокий | 1 823 | 1 479 | 81,13% |

Высокий уровень выделил 20,26% заведений для первоочередной проверки
бизнес-плана. На эту группу пришлось 33,26% всех закрытий на тесте.

Среди закрывшихся заведений модель чаще всего относила к низкому риску
точки с причиной «плохие отзывы о еде» — 62 из 272 (22,79%).
По числу пропусков лидировала высокая аренда — 183 случая.

Обе версии сравнивались на одном test. Качество модели для заведений
Бишкека предстоит проверить на местных данных.

## Как работает проект

Модель по восьми характеристикам ресторана оценивает риск того,
что он не проработает три года. Если оценка достигает порога 0.35,
приложение показывает сигнал для дополнительной проверки.

- `source/eda.py` изучает исходный CSV и обучающую выборку.
- `source/split_data.py` делит данные на train, validation и test
  в пропорции 60 / 20 / 20.
- `source/train.py` обучает модели на train, сравнивает их на
  validation и сохраняет выбранную модель и порог в `artifacts/model.joblib`.
- `source/evaluate.py` считает итоговые метрики на test.
- `app.py` показывает форму в Streamlit и загружает сохранённую модель.

## Локальный запуск на Windows

Скачайте датасет Restaurant Survival с Kaggle. Положите файл
`restaurant_survival.csv` в папку `data/raw/`.

https://www.kaggle.com/datasets/sergionefedov/restaurant-survival-why-they-really-close

Откройте папку проекта в VS Code. Выполните в PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\source\split_data.py
.\.venv\Scripts\python.exe .\source\train_v2.py
.\.venv\Scripts\python.exe .\source\evaluate_v2.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте `Local URL` из терминала, заполните форму и нажмите «Оценить».
Модель обучена на данных Kaggle. Её качество для ресторанов Бишкека
отдельно не проверялось.

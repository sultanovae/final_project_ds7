# Оценка риска закрытия ресторана в первые три года

## Бизнес-задача

Проект помогает предпринимателю определить, какие допущения бизнес-плана
стоит подробнее проверить перед открытием ресторана.

Пользователь вводит семь характеристик заведения. Модель рассчитывает
балл риска закрытия до трёх лет и присваивает низкий, средний или высокий
уровень риска.

Приложение также сравнивает оценки при изменении отдельных параметров,
например при увеличении запаса капитала на два месяца. Такие сценарии
показывают реакцию модели на вводимые значения.

## Данные

Источник — датасет Restaurant Survival — Why They Really Close? на Kaggle.

https://www.kaggle.com/datasets/sergionefedov/restaurant-survival-why-they-really-close

Исходный CSV содержит 45 000 строк и 19 столбцов.
Одна строка соответствует одному заведению. Идентификаторы уникальны,
полных дубликатов строк не обнаружено.

Исходная метка survived_3y показывает, достигло ли заведение трёх лет.
Для модели создана обратная метка closed_before_3y:

- 1 — заведение не достигло трёх лет работы;
- 0 — заведение достигло трёх лет работы.

Доля класса 1 составляет 49,41%.

## Подготовка данных

Стратифицированное разбиение выполнено с random_state=42:

| Выборка | Доля | Строк |
|---|---:|---:|
| Train | 60% | 27 000 |
| Validation | 20% | 9 000 |
| Test | 20% | 9 000 |

Train используется для анализа и обучения, validation — для сравнения
моделей и выбора границ риска, test — для итоговой оценки.

В обучающей выборке по проверенным признакам пропуски отсутствуют.
Категориальный признак кодируется через OneHotEncoder, числовые признаки
масштабируются через StandardScaler. Обработка и модель объединены
в Pipeline. Параметры обработки вычисляются на обучающих данных.

## Выбор признаков

Финальная модель использует семь признаков:

| Признак | Значение |
|---|---|
| location_type | Тип локации |
| is_franchise | Работа по франшизе |
| owner_experience_years | Опыт владельца в годах |
| starting_capital_months | Запас капитала на момент открытия в месяцах |
| foot_traffic | Пешеходный поток, условная шкала 0–10 |
| competition_density | Плотность конкурентов, условная шкала 0–10 |
| has_marketing | Наличие плана продвижения |

Отзывы появляются после открытия. Срок работы и причина закрытия
раскрывают исход, поэтому исключены из входных признаков.
Причина закрытия используется отдельно при анализе ошибок.

### Почему финансовые доли остались в эксперименте

Вариант C с долей аренды и расходов на персонал показал лучший результат
на validation — AP 0,8480.

До открытия предприниматель может знать арендный платёж и планировать
фонд оплаты труда. Доли этих расходов в выручке зависят от её прогноза.
Описание датасета не уточняет, использовалась ли плановая или фактическая
выручка. Для применения модели до открытия требуется уточнить время
измерения и обеспечить сопоставимость показателей.

## Сравнение моделей и наборов признаков

| Эксперимент | AP на validation |
|---|---:|
| Logistic Regression, 8 исходных признаков | 0,6715 |
| Logistic Regression, 11 признаков | 0,7511 |
| Logistic Regression, 13 признаков с финансовыми долями | 0,8480 |
| Logistic Regression, финальные 7 признаков | 0,7501 |
| Random Forest, 11 признаков до настройки | 0,7326 |
| Random Forest, 11 признаков после настройки | 0,7489 |

Для исходной логистической регрессии проверены пять значений C.
Выбрано C = 0.001. При сравнении наборов признаков это значение
зафиксировано и затем использовано в финальной модели.

Для Random Forest через GridSearchCV подобраны максимальная глубина
дерева и минимальное число наблюдений в листе. Подбор выполнялся
кросс-валидацией внутри train.

Сокращение формы с 11 до 7 признаков снизило AP на 0,0010.
Среди 1 800 заведений с самыми высокими оценками число фактических
закрытий изменилось с 1 471 до 1 465. Для демо выбрана короткая форма.

## Результаты на test

Average Precision финальной модели на test составляет 0,7499.
На validation она составила 0,7501.

Границы уровней выбраны по 30-му и 80-му процентилям оценок на validation.
Приблизительные значения границ — 0,388711 и 0,667638.
В приложении используются сохранённые значения с полной точностью.

| Уровень риска | Заведений | Не достигли трёх лет | Доля закрытий внутри группы |
|---|---:|---:|---:|
| Низкий | 2 694 | 594 | 22,05% |
| Средний | 4 483 | 2 374 | 52,96% |
| Высокий | 1 823 | 1 479 | 81,13% |

Высокий уровень выделил 20,26% заведений для первоочередной проверки.
На эту группу пришлось 33,26% всех закрытий на test.

Балл модели относится к введённому профилю. Проценты в таблице описывают
фактические результаты групп заведений в тестовой выборке.

## Анализ ошибок

Пропуском считается закрытие заведения, которому модель присвоила
низкий уровень риска. На test таких случаев 594.

По числу пропусков лидирует высокая аренда — 183 из 1 176 случаев
закрытия по этой причине, или 15,56%.

Самая высокая доля пропусков у причины «плохие отзывы о еде»:
62 из 272, или 22,79%. Следом идут личные причины владельца:
41 из 213, или 19,25%.

Возможное объяснение — стартовые характеристики ограниченно отражают
качество еды после открытия и личные обстоятельства владельца.
Сколько пропусков устранило бы добавление финансовых долей,
отдельно не проверялось.

## Ограничения

- Первая и вторая версии сравнивались на общей тестовой выборке.
- Применимость к ресторанам Бишкека отдельно не проверялась.
- Поток и конкуренция заданы в условных баллах. Для местного применения
  требуется определить сопоставимый способ оценки.
- Низкий уровень также содержит закрывшиеся заведения.
- Изменение балла в сценарии показывает реакцию модели. Фактический
  эффект изменения параметра на закрытия отдельно не измерялся.
- До внешнего применения требуется уточнить происхождение данных,
  период наблюдения, географию и условия лицензии.

## Как работает код

| Файл | Назначение |
|---|---|
| source/split_data.py | Подготовка выборок в data/splits_v2 |
| source/eda.py | Первичный обзор данных |
| source/eda_features.py | Анализ зависимостей по группам |
| source/compare_features.py | Сравнение наборов признаков |
| source/compare_models.py | Сравнение алгоритмов и настройка леса |
| source/train_v2.py | Обучение финальной модели и выбор границ |
| source/evaluate_v2.py | Оценка на test и разбор ошибок |
| app.py | Локальное приложение Streamlit |

Модель, список признаков и границы уровней сохраняются
в artifacts/model_v2.joblib.

Скрипты source/train.py и source/evaluate.py относятся к первой версии.
Они рассчитаны на исходные выборки в data/splits/ и сохранены
для истории экспериментов.

## Локальный запуск на Windows

Скачайте датасет и поместите restaurant_survival.csv в data/raw/.
Откройте папку проекта в VS Code. В PowerShell выполните:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\source\split_data.py
.\.venv\Scripts\python.exe .\source\train_v2.py
.\.venv\Scripts\python.exe .\source\evaluate_v2.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Откройте адрес Local URL из терминала. -m streamlit run app.py
Оставьте терминал со Streamlit открытым во время работы приложения.
